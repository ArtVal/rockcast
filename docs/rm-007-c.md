# RM-007-C — RockCast local favourites and history

**Status:** implemented locally; verification results are recorded with the task hand-off.

RockCast stores one offline-only RM-007-A profile at `%LOCALAPPDATA%\RockCast\personal-profile.v1.json`
(or the existing platform configuration directory / a local fallback). It is UTF-8 JSON with
`schemaVersion: 1`, random local UUIDs, RFC-3339 UTC timestamps, favourites, playback history and
unresolved references. It contains station IDs and safe display snapshots only; it never stores
stream URLs, credentials, relay/Cast state, telemetry or server data.

The profile is atomically replace-written. When lifecycle resolution changes existing records it
first leaves `personal-profile.v1.pre-migration.json`, then writes a small migration journal. An
unsupported schema fails closed and leaves the prior file untouched. Unmapped `legacy-*` and
`rockserver-*` values are quarantined as `legacy-unmapped`; they are not guessed from a URL/name.
The journal records migration counts and the retained backup can be restored only by an explicit
rollback call. Duplicate favourites keep the earliest identity/added time and latest update metadata.

The resolver receives only the accepted local catalog snapshot. Canonical IDs and approved
`legacyIds` are active; merged tombstones follow their unique chain; split, removed and missing
records move to `unresolvedReferences`. The bundled baseline currently has no tombstones, while
the resolver supports them for a future validated offline catalog release. URL or primary-stream
changes leave a record unchanged.

UI: the top bar has a Favourite toggle for the selected station plus adjacent Favourites and History
buttons. Both lists use readable saved names; clicking an available entry selects its stable ID in
the current catalog and starts it through the normal playback path. Missing/lifecycle-unresolved
entries remain stored and are shown as unavailable instead of being selected or deleted. History is
ordered newest-first and can be cleared locally. Playback is recorded after the existing successful
`PlayOk` event, so relay/Cast/local playback orchestration and failed starts are untouched.
RockServer search and voice DTOs preserve the canonical server station ID; URL-derived
`rockserver-*` identities are no longer generated for new personal records.
